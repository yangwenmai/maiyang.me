## 先交代我自己的起点

做 ContextEcho 之前，我没有完整的 iOS 开发经验。

从第一行代码到 App Store 上架，用了 76 天，提交了 468 个 commit，写下约 4.8 万行 Swift。整个过程几乎都在和 Cursor 结对。

中间我做过一次最痛的决定：删掉当时最让我兴奋的全部 AI 功能，一次净删了近 3000 行代码。原因很尴尬，**这些功能我自己根本不会打开**。

所以这篇教程不教你写出更多代码。它教你做出一个**你自己真的会用**的东西。

## 第一步：挑一个你每天都会用的小需求

用这三条筛一遍你脑子里的想法：

- 你自己每天至少会用一次；
- 一句话就能说清它解决什么；
- 第一版只做一件事，几天之内能跑起来。

ContextEcho 的那句话是：**稳稳地听，看见自己的积累**。我的 MVP 用了 3 天。

三条里有一条过不了，换一个想法。别从「做一个 XX 平台」开始。

## 第二步：先跟 AI 聊清楚，再写一页说明

我最开始没有写代码，是先和 ChatGPT 聊想法、定位和该怎么实现。方向清楚了，第一版规划才成形。

聊完以后，把结论写成一页纸。它是给 Agent 看的，也是给一周后的你看的：

```markdown
# 我要做什么

给谁用：我自己（以及和我一样每天 XX 的人）
解决什么：一句话
第一版只做：
1. ...
2. ...
3. ...
明确不做：
- ...
怎么算做完：我能在手机/电脑上 XX，并且 XX
```

「明确不做」那一栏最重要。ContextEcho 写的是：不做节目发现、不做社交、不做推荐流、不做 AI 总结。

## 第三步：在 Cursor 里跑通第一轮

1. 新建一个空文件夹，用 Cursor 打开，先 `git init`；
2. 把上面那页说明存成 `README.md` 放进去；
3. 打开 Agent 对话，第一句话别让它直接写代码，让它先出计划：

```text
读一下 @README.md。先不要写代码。
告诉我：第一版你打算怎么拆，分几步，每一步做完我怎么验证。
有不确定的地方先问我。
```

4. 看计划，删掉你觉得多余的步骤，再让它**只做第一步**；
5. 你自己跑起来看。对了就 commit，不对就把现象原样告诉它。

一轮一轮这么走。我 76 天提交了 468 个 commit，平均一天 6 个多。小步提交的好处是：Agent 改坏了，你随时能退回上一个好的版本。

同一件事你反复跟它说了第三遍，就把它写进项目的 Rules 里，别再靠记忆。

## 第四步：自己天天用，然后砍

能跑起来以后，最重要的事是**自己每天用**。

上架前，我已经连续用了 ContextEcho 72 天，累计收听约 158 小时。哪些功能每天在用、哪些从来不点，用一周就清楚了。

AI 的默认倾向是做加法。你让它继续完善，它会给你更多页面、更多代码，但它很少主动说「这个没必要，删掉吧」。这一刀只能你来砍。

> **先做一个自己每天离不开的东西，再谈给别人用。**

## 常见卡点

**Agent 改着改着，把原来好的地方改坏了。** 回到上一个 commit，把任务拆得更小再来。一次只交代一件事。

**不知道它写的对不对。** 让它告诉你怎么验证，最好是一条命令或者一个操作步骤，你自己跑。

**功能越加越多，越做越累。** 回去看那页说明里的「明确不做」。
